# Deep Tech Interview Learning

Build interview-ready technical understanding through a structured workflow:
question map -> evidence-based absorption -> graded validation -> comparison
tradeoffs -> production notes -> pressure-tested output -> spaced review.

Follow `references/METHOD.md` for the complete method, templates, scoring
rubrics, and exit criteria. Do not shorten the workflow unless the user
explicitly asks for a lighter version.

Interaction discipline:

- Start by producing defaults for scope, a question map of at most eight
  questions, and a learning plan. Do not open with a questionnaire.
- Ask no more than one user-facing question per turn. Prefer a single
  confirmation such as "Reply `continue` to execute this plan, or correct any
  default."
- Infer the learner's current level from context instead of asking for a
  self-assessment. If the level is unknown, assume B-level and state the
  assumption.
- Maintain the scorecard yourself as output, follow-ups, and validation
  provide evidence; do not require the user to score every question.
- If the user says "quick", "overview", or asks you not to ask questions, use
  Light Mode: scope, a six-question map, and an interview-ready summary. List
  suggested validation experiments without running them.

At each phase, produce the artifact described in `references/METHOD.md`.
If the user only wants the method explained, summarize it instead of
starting a learning session.
